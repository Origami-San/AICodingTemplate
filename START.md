# Старт нового проекта — пошаговый гайд

Мини-инструкция, что сделать **до первой строчки кода**, когда копируешь этот шаблон под новый проект. После прохождения всех шагов работа идёт строго по `ROADMAP.md` и `AGENTS.md` — этот файл больше не нужен.

## Шаг 0. Скопировать шаблон

Скопировать содержимое репозитория в новую папку проекта. Это отдельная копия — не форк и не подпапка текущего шаблона.

## Шаг 1. Собрать исходные материалы

Прежде чем звать агента, собери то, что у тебя уже есть (не обязательно всё сразу):

- бриф или описание идеи — своими словами, не обязательно оформленное;
- переписка/заметки, где обсуждались детали;
- ссылки на похожие сайты/приложения, скриншоты, референсы;
- если стек уже решён — какой именно и почему.

Ничего из этого не обязано быть готовым документом — скилл на следующем шаге сам разберёт это через интервью.

## Шаг 2. Запустить `tzroadmap-product` — собрать ТЗ и роадмап

Это ключевой шаг. Не заполнять `TZ.md`/`ROADMAP.md` вручную — их строит скилл.

```
используя скилл tzroadmap-product, составь ТЗ на <краткое описание проекта>
```

Что произойдёт:

1. Скилл прочитает то, что ты дал, и разделит на подтверждённое / требующее решения.
2. Короткое интервью — максимум две волны вопросов (цель, аудитория, сценарии, границы версии; затем то, что специфично типу проекта). Не отвечай на то, что не спрашивают — лишнего не будет.
3. **Стек и внешние сервисы** — отдельный обязательный пункт интервью. Если готового решения нет, скилл предложит варианты с компромиссами и явно пометит выбор как открытый (`OPEN-xx`), а не придумает его сам.
4. На выходе — три файла: `TZ.md` (требования), `ROADMAP.md` (этапы 0–7, только применимые, с чекбоксами), и дополненный `AGENTS.md` (короткие правила продолжения работы).

Если по ходу работы требования изменятся — не редактировать `TZ.md`/`ROADMAP.md` руками, а снова звать тот же скилл: он покажет дельту (что меняется и почему) и обновит файлы, сохранив уже выполненные `[x]`.

## Шаг 3. Проверить черновые заготовки под стек

В корне шаблона есть `.htaccess` — черновая заготовка на случай стека PHP + Apache. Если в `TZ.md` (шаг 2) выбран другой стек (Node, статика и т.д.) — удалить или адаптировать. Если стек PHP/Apache — оставить и адаптировать под проект.

## Шаг 4. Подготовить `.env`

Скопировать `.env.example` в `.env` и заполнить реальными значениями по мере подключения сервисов, выбранных в `TZ.md` (шаг 9 ТЗ — стек и инфраструктура). `.env` в Git не попадает — секреты только там, не в коде и не в документации.

## Шаг 5. Собрать визуальные референсы

Понадобятся на первом шаге этапа 1 «Frontend» — там `DESIGN.md` собирается вместе с агентом на основе того, что реально нравится/подходит: скриншоты, ссылки на сайты, палитры, шрифты. Собери это заранее, вне репозитория — само `DESIGN.md` заполнять сейчас не нужно, шаблон намеренно оставляет его пустым до этого шага.

## Шаг 6. Создать репозиторий

Создать GitHub-репозиторий и связать с ним локальный проект (`git remote add origin ...`). Дальше `git commit` — после каждой готовой фичи (правило из `AGENTS.md`), `git push` — только по отдельной команде.

## Шаг 7. Начать работу по `ROADMAP.md`

Работать с первого `[ ]` самого раннего незавершённого этапа, порядок этапов не менять. Первая задача этапа 1 «Frontend» — собрать `DESIGN.md` (шаг 5 уже подготовил для неё материал), дальше — вёрстка блоками на макетных данных.

С этого момента все решения о том, что делать дальше, — из `ROADMAP.md`, все правила работы — из `AGENTS.md`. Если нужен обзор доступных скиллов для конкретной задачи — `SKILLS.md`.

## Чек-лист перед стартом

- [ ] Шаблон скопирован в новую папку
- [ ] Материалы/бриф/референсы собраны (хотя бы черновые)
- [ ] `tzroadmap-product` запущен → `TZ.md` + `ROADMAP.md` готовы, стек зафиксирован или помечен `OPEN-xx`
- [ ] `.htaccess` проверен под выбранный стек
- [ ] `.env` создан из `.env.example`
- [ ] Визуальные референсы для дизайна собраны
- [ ] GitHub-репозиторий создан и связан
- [ ] Можно начинать первый `[ ]` в `ROADMAP.md`
