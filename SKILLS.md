# Скиллы проекта — как вызывать вручную

Справочник по всем скиллам, установленным в `.claude/skills/` и `.agents/skills/` (работают и в Claude Code, и в Codex). Скилл может сработать автоматически по контексту запроса, но надёжнее всего — вызвать его явно.

**Универсальный шаблон явного вызова:**

```
используя скилл <имя-скилла>, <что сделать>
```

Например: «используя скилл deslop, проверь эту страницу».

> Скиллы читаются при старте сессии. Если скилл только что установлен — нужен перезапуск сессии, иначе он не появится в списке доступных.

## Дизайн и фронтенд

### `frontend-design`
Общая эстетическая база: типографика, палитра, композиция — чтобы дизайн не выглядел шаблонно/дефолтно.

- Само срабатывает на: любую новую вёрстку страницы, лендинга, компонента с нуля.
- Явный вызов: `используя скилл frontend-design, сделай дизайн главной страницы`

### `taste-skill`
Более строгий анти-шаблонный скилл именно под лендинги, портфолио и редизайны: сам определяет стиль по брифу, задаёт три «дизайн-параметра» (variance/motion/density), даёт готовый чек-лист перед сдачей.

- Само срабатывает на: лендинг, портфолио, редизайн существующей страницы.
- Явный вызов: `используя скилл taste-skill, сделай лендинг для <продукт>`

### `ui-ux-pro-max`
База данных готовых UI/UX-решений: стили, палитры, шрифтовые пары, иконки, GSAP-анимации, чарты, паттерны — под конкретный стек (React, Vue, Flutter, SwiftUI и т.д.). Подходит и для дашбордов/приложений, не только лендингов.

- Само срабатывает на: выбор цвета/шрифта/анимации/иконок, ревью доступности и адаптива, вопросы по конкретному стеку.
- Явный вызов: `используя скилл ui-ux-pro-max, подбери дизайн-систему для <продукт>`

### `deslop`
Точечная чистка уже написанного кода/вёрстки от типовых AI-признаков (градиенты, glassmorphism, дефолтные бейджи и т.п.), без изменения бренда и функциональности.

- Само срабатывает на: жалобы «выглядит как сгенерированное», «убери слоп».
- Явный вызов: `используя скилл deslop, проверь <файл/страницу>`

**Как выбрать между четырьмя дизайн-скиллами:** новый лендинг/портфолио → `taste-skill`; выбор конкретной библиотеки/палитры/анимации под ваш стек → `ui-ux-pro-max`; общая эстетическая база при любой новой вёрстке → `frontend-design`; чистка уже готового результата от шаблонности → `deslop`.

## Код

### `refactor`
Аудит и пошаговый рефакторинг кода без изменения поведения: сначала таблица с приоритетами и риском/выхлопом, правки — только после вашего согласия.

- Само срабатывает на: «отрефактори», «почисти код», «код слишком запутанный», «тут каша».
- Явный вызов: `используя скилл refactor, проведи аудит <файл/модуль>`

### `tzroadmap-product`

## SEO

Особый случай: это **два разных набора скиллов от одного автора** (AgriciDaniel), каждый специально под своего агента — они НЕ зеркалируются друг в друга, в отличие от всех остальных скиллов этого проекта:

- `.claude/skills/` — 26 скиллов из репозитория `claude-seo`.
- `.agents/skills/` — 27 скиллов из репозитория `codex-seo`. Состав чуть другой (например есть `seo-firecrawl`, `seo-performance`, `seo-visual`, но нет `seo-agentic`, `seo-content-brief`) — это осознанно, авторские версии под каждого агента отличаются.

Установлена только **текстовая часть** (`SKILL.md` + `references/`), без ~50 Python-скриптов, хуков и суб-агентов из оригиналов. Это значит:

- скиллы дают методологию, структуру аудита и чек-листы;
- команды вида «запусти `scripts/...>`», встречающиеся в некоторых `SKILL.md`, выполняться не будут — самих скриптов в проекте нет;
- реальные интеграции (Google Search Console, DataForSEO, Ahrefs, GA4 и т.д.) не подключены — при необходимости их ставить отдельно и обсуждать API-ключи.

Точка входа — хаб-скилл `seo`, остальные — специализированные: `seo-audit`, `seo-page`, `seo-technical`, `seo-schema`, `seo-sitemap`, `seo-content`, `seo-images`, `seo-hreflang`, `seo-backlinks`, `seo-local`, `seo-maps`, `seo-geo` (AI Overviews), `seo-ecommerce`, `seo-cluster`, `seo-plan` и другие.

- Само срабатывает на: «сделай SEO-аудит», «проверь schema/sitemap/технический SEO», «hreflang», «backlinks».
- Явный вызов хаба: `используя скилл seo, сделай аудит <url>`
- Явный вызов конкретного: `используя скилл seo-technical, проверь техническое SEO <url>`

## Управление и аудит скиллов (мета)

Проект — мультиагентный шаблон: каждый скилл ставится сразу в две папки — `.claude/skills/<name>/` (Claude Code) и `.agents/skills/<name>/` (Codex, сканирует эту папку иерархически вверх по каталогам). Обе копии должны быть побайтово идентичны. По умолчанию скиллы ставятся только в этот проект — глобально (`~/.claude/skills`, `~/.agents/skills`) только по отдельной просьбе.

### `install-skill`
Устанавливает новый скилл в проект (из GitHub-репозитория, из локальной папки-черновика или с нуля) с учётом мультиагентности: куда класть, как проверять на промпт-инъекции и скрытые хуки/бинарники перед установкой, как сверять копии для Claude/Codex, когда обновлять этот `SKILLS.md`.

- Само срабатывает на: «установи скилл X», «добавь скилл из <ссылка>», «обнови скилл X».
- Явный вызов: `используя скилл install-skill, установи скилл <имя/ссылка>`

### `auditing-agents-md`
Проверяет сам `AGENTS.md` — расположение, противоречия с другими правилами, исполнимость (секреты, `.gitignore`, git), качество формулировок.

- Явный вызов: `используя скилл auditing-agents-md, проверь AGENTS.md`

### `auditing-skills`
Проверяет любой другой скилл в проекте — структуру папки, frontmatter, обнаружение в сессии, битые ссылки на `references/`, компактность.

- Явный вызов: `используя скилл auditing-skills, проверь скилл <имя>`

## Проверка, что скилл реально подключён

Спросить: «какие скиллы сейчас доступны в сессии?» — либо напрямую вызвать нужный по шаблону выше и посмотреть, откроется ли он (если скилл не найден, будет ошибка «Unknown skill»).
