# Аудит AGENTS.md

Проводи аудит без изменения файлов, если пользователь явно не попросил исправления. Оценивай фактические файлы, а не предполагаемую структуру.

## Проверка

1. Найди все `AGENTS.md`: сначала в корне, затем вложенные. Определи область действия каждого файла.
2. Прочитай корневой `AGENTS.md` и связанные источники, на которые он ссылается: например, `TZ.md`, `ROADMAP.md`, `DESIGN.md`.
3. Сопоставь проектные инструкции с доступными глобальными правилами. Ищи только реальные противоречия: более конкретное правило в проекте не является конфликтом само по себе.
4. Проверь техническую исполнимость правил:
   - наличие и кодировку `AGENTS.md`;
   - `.gitignore` для `.env`, `.env.*` и исключения `.env.example`;
   - работоспособность Git, если инструкция требует коммиты;
   - отсутствие опасных глобальных масок в `.gitignore`, которые могут скрыть нужные исходники, lock-файлы или тестовые артефакты.
5. Проверь качество содержания: порядок приоритетов, источник требований, зависимые решения (`OPEN-*`), границы самостоятельности, правила приёмки, секреты, Git, запреты на разрушительные операции и специфичные для проекта ограничения.

## Оценка

Выставляй 0–10 по каждому применимому критерию:

| Критерий | Что подтверждать |
|---|---|
| Расположение и охват | Корневой файл и отсутствие неожиданных вложенных правил |
| Совместимость | Нет противоречий глобальным и пользовательским инструкциям |
| Управление требованиями | Понятны источники требований, состояния и зависимостей |
| Исполнимость процесса | Правила можно выполнить в текущем репозитории |
| Безопасность | Секреты защищены и не попадают в Git |
| Поддерживаемость | Нет ненужного дублирования и неоднозначностей |

Не занижай оценку за необязательное улучшение. Отделяй проблемы `AGENTS.md` от проблем окружения: например, повреждённый Git делает правило коммитов временно неисполнимым, но не обязательно неверным.

## Формат ответа

Начинай с итогового вердикта. Затем дай компактную таблицу «критерий — оценка — доказательство». Разделяй замечания на:

- критичные блокеры;
- рекомендуемые исправления;
- необязательные улучшения.

Для повторного аудита явно укажи, какие прежние замечания закрыты, а какие остались. Не редактируй `AGENTS.md`, `.gitignore` или Git-конфигурацию без отдельного запроса.
