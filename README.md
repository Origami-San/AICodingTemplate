## Что это за репозиторий

Это шаблон (template) для старта новых проектов, которые пишутся вместе с AI-агентами. Не самостоятельный проект, а заготовка: копируешь этот репозиторий в новую папку — и начинаешь программировать вместе с агентом по единым, заранее продуманным правилам.

Шаблон рассчитан на работу сразу с **двумя агентами** — Claude Code и Codex — по одним и тем же правилам, без дублирования логики вручную.

## Как устроена работа с двумя агентами

Оба агента читают инструкции по-разному, но правила должны быть одни и те же — поэтому они не дублируются, а подключаются:

- **`AGENTS.md`** — единственный источник правил проекта. Именно этот файл нужно редактировать, когда правила меняются.
- **`CLAUDE.md`** — файл для Claude Code. Он не содержит своих правил, а всего одной строкой (`@AGENTS.md`) подключает содержимое `AGENTS.md`. Codex читает `AGENTS.md` напрямую.

Это значит: **правила всегда правь только в `AGENTS.md`.** `CLAUDE.md` трогать не нужно — он просто зеркало.

То же самое с навыками (skills) агентов:

- **`.agents/skills/`** — навыки для Codex.
- **`.claude/skills/`** — те же навыки для Claude Code.

Содержимое этих двух папок идентично (это буквально одни и те же файлы, продублированные под разные пути, которые ищут разные агенты). Обновляя навык, обновляй его в обеих папках.

## Карта файлов и папок

| Файл / папка | За что отвечает |
|---|---|
| `AGENTS.md` | Главные правила проекта для агента: как коммитить, что нельзя делать без спроса, ограничения дизайна, порядок работы по этапам. Источник правды для обоих агентов. |
| `CLAUDE.md` | Просто подключает `AGENTS.md` (`@AGENTS.md`). Не редактируется отдельно. |
| `TZ.md` | Техническое задание — источник **требований** к конкретному проекту. Заполняется в начале работы над проектом (в шаблоне пуст). |
| `ROADMAP.md` | План по этапам — источник **текущего состояния** проекта: что сделано (`[x]`), что нет (`[ ]`). Работа всегда продолжается с первого невыполненного пункта. |
| `DESIGN.md` | Дизайн-система проекта (цвета, отступы, компоненты). Появляется и заполняется на этапе фронтенда. |
| `.agents/skills/` | Навыки (skills) для Codex — готовые инструкции под конкретные задачи (аудит AGENTS.md, деслоп, дизайн, тон-роадмап и т.д.). |
| `.claude/skills/` | Те же навыки, но по пути, который читает Claude Code. |
| `.env.example` | Шаблон переменных окружения без реальных секретов — только безопасные примеры. Реальные значения хранятся в `.env`, который в Git не попадает. |
| `.gitignore` | Что не попадает в Git: `.env`, node_modules/vendor, кэш, логи, аплоады, бэкапы и т.д. |
| `.editorconfig` | Базовые настройки редактора (отступы, кодировка, конец строки) — одинаковые для всех, кто открывает проект. |
| `.prettierignore` / `prettier.config.js` | Настройки автоформатирования кода и список файлов, которые форматировать не нужно. |
| `.htaccess` / `php.ini` | **Черновые заготовки** на случай, если конкретный проект будет на PHP + Apache. Это не обязательный стек шаблона — при старте нового проекта с другим стеком (Node, статика и т.д.) эти файлы нужно удалить или адаптировать под выбранный в `TZ.md` стек. |

## Навыки (skills) в комплекте

| Навык | Для чего |
|---|---|
| `tzroadmap-product` | Помогает согласовать `TZ.md` и `ROADMAP.md` перед стартом или перепланированием проекта. |
| `frontend-design` | Помощь с визуальным направлением, типографикой и осмысленным дизайном интерфейса. |
| `taste-skill` | Анти-шаблонный дизайн для лендингов, портфолио и редизайнов. |
| `deslop` | Проверка и чистка типичных «ИИ-шаблонных» признаков в дизайне сайта/интерфейса. |
| `ui-ux-pro-max` | База знаний по UI/UX: стили, палитры, шрифтовые пары, чек-листы доступности, стек-специфичные рекомендации. |
| `auditing-agents-md` | Аудит `AGENTS.md`: расположение, противоречия с другими правилами, исполнимость, безопасность. |
| `auditing-skills` | Аудит самих навыков: метаданные, структура, готовность к использованию. |

## Как начать новый проект на основе шаблона

1. Скопируй содержимое этого репозитория в новую папку проекта.
2. Заполни `TZ.md` — требования и подтверждённый стек.
3. Начни вести `ROADMAP.md` по этапам, не забегая вперёд.
4. Проверь `.htaccess` и `php.ini` — удали или адаптируй, если стек проекта не PHP/Apache.
5. Работай с агентом по правилам из `AGENTS.md` — он главный источник правды для обоих агентов.

## Ограничения дизайна (кратко)

Полный список — в `AGENTS.md`, раздел «Ограничения дизайна». Коротко: без glassmorphism, перегруженных градиентов, неонового свечения, мелкого текста (менее 16px) и декоративных blob-фигур.
